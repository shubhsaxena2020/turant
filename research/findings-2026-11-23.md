# Findings, 23 Nov 2026 (harness + model experiments)

## Numbers so far (280-case corpus, 7 languages)

| Pipeline | Cases fully correct | Notes |
|---|---|---|
| Rules (`extract.ts`) on perfect text | 55.7% | strong in hi/en (80/88%), weak in bn/ta/te/kn number words (32–47%) |
| NIM nemotron-3.5-bolt on perfect text | **92.1%** | 93–99% field accuracy in every language, median 1.3 s; weakest field = amounts (10/166 wrong) |
| NIM nemotron-3-ultra on perfect text | 90.7% | slower (1.7 s), 22 amount errors; bolt is the pick |
| Rules through Whisper large-v3-turbo (clean audio) | 18.8% (interim smoke, 324 runs) | hi 61%, en 73%, but ta 0%, kn 4.5%, bn 2.9%: Whisper WER 75–130% on Dravidian and Bengali |

## What this means for the Round 2 build

1. **Understanding = hybrid.** The LLM (bolt via `/api/understand`) reads the free speech. Rules own numbers and IDs, and every number the LLM proposes is truth-checked against the rules. Without network, the app falls back to rules only.
2. **Speech = Chrome Web Speech first, not Whisper.** Whisper turbo is not usable for Tamil, Kannada, Telugu or Bengali. Chrome's recogniser (Google's) is what phones use, but it **cannot be benchmarked automatically**: driving real Chrome with a WAV as a fake microphone fires every audio and speech event, yet Google's service returns no transcript to an automated browser. Test it on a real phone (script below).
3. **A server ASR fallback for Indian languages needs a key from Shubh** (free, no card):
   - Sarvam AI ("saarika" STT and "bulbul" TTS; built for Indian languages);
   - or Groq (hosted Whisper; fast, but the same Whisper weaknesses).

   Prefer Sarvam.

## 10-minute real-phone test for Shubh (Android Chrome)

Open the Turant build on the phone. Run `npm run dev -- --host` in `prototype/` on the laptop. The mic only works on HTTPS or localhost, so on the phone open `chrome://flags/#unsafely-treat-insecure-origin-as-secure`, add `http://<laptop LAN IP>:5173`, relaunch Chrome, and open that URL (same Wi-Fi). A deployed HTTPS link avoids this step. For each of hi, ta, bn and kn: pick the language, tap the circle, read the matching sample story from `prototype/src/i18n/samples.ts` aloud, and note what appears as live text. If ta, bn or kn come out badly, a Sarvam key goes first on Round 2 day 1.
